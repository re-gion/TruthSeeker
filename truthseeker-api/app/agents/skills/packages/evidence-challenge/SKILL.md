# 证据质询与收敛控制 Skill

## 适用场景

用于审查当前 Forensics 或 OSINT 阶段的证据充分性、冲突、降级影响与补证必要性。

## 输入边界

质询只针对当前阶段；历史经验只能减少冗余质询，不能覆盖新证据或跨阶段改写结论。阶段分工是硬边界：电子取证 Agent 只负责检材本体鉴伪，WHOIS、IP、DNS、域名溯源与公开情报搜索是情报溯源 Agent 的职责；不得把其他阶段职责事项作为当前阶段的质询点或打回理由，也不得把“缺少多工具复测/像素级/OCR 等额外分析”当作质量缺陷。交叉验证指取证视角（是否伪造）与溯源视角（是否虚假/恶意）的跨 Agent 互证；已通过阶段质询的上游结论属于可信结论，下游应引用而非另起分歧判断。若 OSINT 报告已包含系统确定性注入的“上游已核验结论引用”小节且正文未与上游数值冲突，不得再把叙事措辞归属或引用粒度作为阻断性质询点。经验/类案 RAG 要求的验证动作若超出当前已配置工具能力（如要求社交媒体、应用商店、工商信息核验而未配置），不得作为质询点、打回理由或降低置信度的依据。搜索正常执行后零命中且报告已说明搜索覆盖的，属于有效负结果，不得以“未检出”为由要求补充不存在的验证渠道或反复打回。

## 标准步骤

1. 读取确定性问题、工具状态、证据板和当前阶段输出。
2. 定位矛盾、无来源主张、降级误读和证据缺口。
3. 把问题转成可执行的补证动作并限定目标 Agent。
4. 解释放行、打回或轮次上限下的残留风险。

## 允许工具

使用运行时提供的模型交叉审查、个人经验 RAG、确定性质量分、阶段轮次和协同状态。

## 证据门槛

高严重度问题和低置信度必须服从 Python 硬门槛；模型建议不能越过最大轮次、阶段边界和协同触发规则。

## 禁止事项

不得跨阶段打回，不得把模型置信度当作唯一收敛依据，不得把个人经验写成当前案件事实。

## 输出要求

输出质询对象与置信度、主要质询点、打回或放行建议、收敛依据和残留风险。

## 自检清单

- 目标 Agent 是否等于当前阶段。
- 每个问题是否有证据或明确缺口。
- 补证动作是否可执行且不重复。
- 放行是否解释硬门槛或轮次上限。

## 降级策略

Skill 不可用时保留确定性硬门槛和系统提示词路径，并在日志、审计与结果中记录未加载或校验失败。
