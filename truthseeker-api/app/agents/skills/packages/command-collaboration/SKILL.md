# 研判指挥与协同编排 Skill

## 适用场景

用于 Commander 的最终研判、协同主持和协同结束后的经验沉淀；调用点显式选择工作流，不做动态路由。

## 输入边界

只消费现有 Agent 结果、确定性分数、真实人类消息、已确认协同摘要和可审计参考。不得将模型内容改称人工意见。

## 标准步骤

先确认当前工作流和输入边界，再按所选工作流执行；所有评分、四分类、路由和公共字段服从确定性 Python。

## 工作流

### final_adjudication

解释最终四分类裁决，核对结构化综合置信度、Agent 权重、证据链完整性、关键分歧、残留风险和后续建议。不得让 LLM 自行改写 `final_verdict`。

### human_collaboration

合并语义重复的求助点，保留不同根因与目标 Agent；把问题整理成专家可执行任务。协同结束时只总结真实用户与专家回复、依据、未解决项和回注建议。

### experience_distillation

从已结束且可复用的协同中生成脱敏经验草稿，只保留方法、判据、补证路径、升级条件和限制；删除检材名、链接、账号与可识别案件细节。

## 允许工具

使用运行时已提供的 Agent 结果、证据板、协同消息、确定性权重与报告生成接口；不安装新工具，不直接修改数据库协议。

## 证据门槛

最终结论引用结构化 `final_verdict`；人工意见只来自真实人员消息；无可复用协同内容时经验草稿必须为空。

## 禁止事项

不得创建第五类裁决，不得把类案 RAG 改写成当前事实，不得把加载成功写成检查通过，不得绕过用户确认保存经验。

## 输出要求

所选工作流必须遵守对应系统提示词和现有 JSON/Markdown 协议；不输出其他工作流的内部步骤。

## 自检清单

- 是否选择了明确工作流。
- 是否引用确定性字段而非自行估分。
- 是否区分自主观察和人工意见。
- 是否保留降级、未解决项与确认边界。

## 降级策略

Skill 缺失、损坏或版本不兼容时继续系统提示词路径，在日志、审计和报告中记录实际状态，不声称本轮采用 Skill。
